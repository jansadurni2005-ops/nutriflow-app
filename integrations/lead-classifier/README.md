No se ha instalado nada en tu ordenador ni en tu bandeja. Los precios y límites de tus servicios existentes siguen dependiendo de tus contratos; si tu plan de Manychat no incluye API, el piloto se detiene y no contrata una mejora.

**Para verlo sin tocar la bandeja:** descarga el ZIP de esta rama desde GitHub → Code → Download ZIP y descomprímelo. Con Node.js 22+ y Ollama de escritorio instalados, abre esta carpeta y haz doble clic en **Probar-en-Windows.cmd**. La primera vez descargará un modelo de unos 2,5 GB. Muestra los resultados de tres tandas de conversaciones ficticias. No necesita claves ni la sesión de Instagram. No hace falta comprar un ordenador nuevo. Mantén Ollama vinculado a 127.0.0.1 y las funciones cloud desactivadas si lo usas con texto privado. La aplicación solo ofrece un modelo local; no tiene ruta alternativa de pago.

## Qué hace

- Reconoce significado a partir de ambos participantes y separa llamada, recurso, receta, objetivo nutricional, objeción económica, negativa y falta de contexto. Los errores y ambigüedades se apartan para revisión. El valor de confianza es un indicador fijo de decisión clara/ambigua, **no** una probabilidad calibrada.
- El ensayo usa exclusivamente un contacto designado. Comprueba los IDs de propietario, contacto y participantes por APIs oficiales. Si los identificadores no se corresponden entre apps, se detiene. No vincula por nombre ni por foto.
- Solo mensajes de texto. Historial parcial, un participante inesperado, medios o respuestas demasiado largas impiden la escritura. No almacena transcripciones. No hay rutas de envío, visto, apertura/cierre o cambio de automatizaciones. Meta y Manychat ya alojan el chat; el clasificador no envía texto a un proveedor externo de IA.
- Usa el nivel principal en un campo y seis condiciones independientes. Escribir un campo no garantiza la retirada de un seguimiento comercial preexistente; no se debe tratar una etiqueta como baja efectiva. El piloto no retira una baja/cliente previamente registrada en sus campos. No desplegar sobre contactos comerciales hasta integrar la lista autoritativa y verificar los flujos existentes.

## Prueba oficial con UN usuario de pruebas

**No iniciar si la evaluación falla. La herramienta exige tres tandas locales aprobadas con el mismo modelo y código antes de crear campos o escribir. La comprobación caduca a los siete días.** Hace falta una cuenta secundaria de prueba, no un cliente real. No se deben compartir contraseñas, códigos ni tokens en un chat, un archivo de Git o una captura. Nunca regeneres una clave activa si la usan otras integraciones. No conviene desconectar Manychat de Instagram ni cambiar Conversation Routing. Si Meta no entrega los mensajes necesarios como segunda integración, se cancela el piloto.

**Asistente para Windows:** después de las pruebas locales, ejecuta `Piloto.ps1` en PowerShell desde esta carpeta. Pide las claves con entrada oculta, contrasta el @ de pruebas con su ID en Manychat y verifica el vínculo en Meta. No pegues claves en los comandos ni en el chat. Puedes detenerte tras ver el resultado, sin escribir nada.

1. Autorizar el acceso de la app propietaria a los mensajes de Instagram para la prueba; en Instagram Login, verificar los permisos de cuenta y de mensajes. La credencial de métricas sin permiso de mensajes no basta. Disponer de clave **de la cuenta** Manychat (Ajustes → API) en el plan actual. Introducir solo **en la sesión local privada** los dos secretos.
2. Designar el ID de contacto de pruebas en Manychat y el correspondiente Instagram-scoped ID obtenido de la integración oficial. Confirmar que el operador controla esa cuenta. No obtenerlos leyendo chats mediante el navegador automatizado.
3. Desde la cuenta de prueba, enviar el texto acordado. Jan verifica visualmente que aparece en No leídos **sin abrirlo**. En el ordenador local: ejecutar `node pilot.mjs inspect` y luego `node pilot.mjs preview`. Estos modos hacen solo GET a Meta y Manychat; el modelo usa HTTP local. Guardar la revisión devuelta por preview.
4. Auditar que ningún flujo existente reaccione a los campos con prefijo SN. Tras comprobar que el plan incluye campos personalizados y API sin coste adicional, `node pilot.mjs fields` crea solo los campos nuevos del clasificador. No reconfigura etiquetas, reglas ni mensajes de otros flujos. Si hay nombres incompatibles, aborta; un fallo parcial se puede reintentar.
5. `node pilot.mjs stamp` escribe el resultado **solo** en ese contacto y solo para la revisión probada, con nueva comprobación de identidad y lectura del campo para confirmar. Comprobar en Inbox sin abrir la conversación: el mismo chat sigue como no leído y aparece en el filtro de nivel, el estado Open/Closed no cambió y el usuario de prueba no recibió un nuevo DM. La API pública consultada no confirma el estado Unread de Manychat. Sin observación humana, no dar por superada la prueba A.
6. Solo tras esas comprobaciones, `node pilot.mjs watch-tester` observa **exclusivamente ese contacto** cada minuto durante diez minutos para probar intercambios manuales. Sigue requiriendo el mismo PC encendido. No activar para todos; el resto de mensajes sigue su flujo normal.

Variables privadas de sesión: `SN_MC_TOKEN`, `SN_IG_TOKEN`, `SN_TEST_MC_ID`, `SN_TEST_IG_ID`. Confirmación para crear campos o escribir: `SN_TEST_CONFIRM=ONE_TESTER`; para escribir: `SN_TEST_FIELDS_AUDITED=YES` y `SN_TEST_REVISION` de preview. Para watch-tester además `SN_TEST_UNREAD_PASSED=YES` después del control real. Estos controles **no** convierten el programa en un servicio autorizado multiusuario. No publicarlo como API. En PowerShell 7 se puede introducir un secreto sin eco con `$env:SN_MC_TOKEN = Read-Host -MaskInput 'Clave de cuenta Manychat'` y análogamente para Instagram; cerrar la sesión al terminar. No ejecutar herramientas desconocidas en esa sesión.

## Vista prevista en tu Manychat

Si tu cuenta lo permite, configura una etiqueta de Inbox o filtro con `SN Interés = hot`, `SN Revisar = false`, `SN current_client = false`, `SN do_not_contact = false` y combínalo con **No leídos**. Para templados usa `warm`. Llamada pendiente: `SN call_accepted = true` y `SN call_scheduled = false`. Para nutricionista, usa la condición independiente `SN has_nutritionist = true`. Estas reglas de Inbox no se han creado en la cuenta. No atribuir un seguimiento detenido a una condición que no está integrada en un flujo.
